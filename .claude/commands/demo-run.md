---
description: Full run for a client and month. Same steps as /monthly-analysis, but every file ends up in its own permanent folder runs/runN/ (with that run's evals) and shows as its own run in the UI
argument-hint: <client> <YYYY-MM> [--with-regress]   (example: abc 2026-06)
allowed-tools: Bash(python scripts/new_run.py *), Bash(python src/monthly_review.py *), Bash(python src/commentary_retry.py *), Read, Write, Edit, Agent
---

Run a full analysis for **$ARGUMENTS** (client id, then month as YYYY-MM, optionally `--with-regress`). Work from the repo root. If client or month is missing, stop and ask.

`<RUN>` below means the folder printed in step 0, for example `runs/run3`, and `<DIR>` means `<RUN>/_work/<client>`: the working folder the engine scripts write into. Pass `--outputs-root <RUN>/_work` to every script that takes it. Nothing is written to `outputs/`. Never delete `runs/` or any run folder; if something fails, the folder stays and step 7 records it as failed.

**Timings.** Around every stage below run `python scripts/new_run.py mark <RUN> "<stage>" start` just before it and `python scripts/new_run.py mark <RUN> "<stage>" end` right after it, so run.json records start, end and duration for each. Stage names, exactly: `Skill draft`, `Grade attempt 1`, `Grade attempt 2` (only if the retry runs), `Review (first)`, `Revise` (only if the first review asked for changes; otherwise `finish` records it as skipped), `Review (final)`, `Final grade`, `Package`. Intake and Calculate are timed by step 0 itself. Never edit run.json by hand.

0. **Create the run folder.** Run `python scripts/new_run.py <client> <month> --claude`. It makes the next free `runs/runN/`, runs intake and calculate into `<RUN>/_work/<client>/` and prints the folder path. If it refuses (invalid client or month, unknown client) stop and report. If the pipeline failed, go straight to step 7 with `--failed "<reason>"`; do not fall back to `outputs/`.
1. **Draft the commentary** (stage `Skill draft`) following the `monthly-financial-analysis` skill, using only the packet's numbers. Write `<DIR>/commentary_<month>.md` in the fixed section order with a `##` heading for each: Headline · Revenue · Margins · Opex · Cash & runway · One-offs · Questions. Under the headings, one statement per line, numbered `1.`, `2.`, `3.` … continuing across sections, no other numbered lines. Include the same-month-last-year comparison (packet `yoy`) and net income excluding one-offs (packet `adjusted_net_income`). Cover revenue, gross profit, operating expenses and net income with MoM and margins; name all three `top_movements`; state TTM only if the packet has it; state the cash balance and runway if the packet has `cash`; mention each data-quality warning and any one-off in the month. Describe what changed, never why. Put no causes, forecasts or recommendations in the statements. Then write the identical text to `<DIR>/commentary_<month>_draft.md` (this is Claude's first draft; the UI compares it with the final text).
2. **Grade, retry once** (stages `Grade attempt 1`, then `Grade attempt 2` around the regrade). Run `python src/commentary_retry.py grade <client> <month> --outputs-root <RUN>/_work`. If it passes, go on. If it fails, it prints the grader's exact mismatches: fix exactly those items, ONCE, rewrite `<DIR>/commentary_<month>.md` with Write (not the `_draft` file), then run `python src/commentary_retry.py regrade <client> <month> --outputs-root <RUN>/_work`. If the regrade still fails, do not try again: the record says `NOT APPROVED` with `needs_human`. Continue anyway and say in the report that a human must fix the commentary.
3. **Review** (stage `Review (first)`). Spawn the `finance-reviewer` subagent with the two file paths (packet and commentary) and no other context. It must cite a statement number for every change and return the four checklist scores (numbers, coverage, causes, tone). Save its JSON block, unchanged, as `<DIR>/review_<month>.json` AND as `<DIR>/review_<month>_first.json` (the UI compares first and final).
4. **Revise once** (stage `Revise` around the rewrite, then `Review (final)` around the second reviewer run). If the verdict is `changes`, fix only what the changes list says, rewrite the whole commentary file `<DIR>/commentary_<month>.md` with Write (keep the numbering), and run the reviewer again. Save the new review unchanged as `<DIR>/review_<month>.json` only; leave `_first.json` as it is. Never edit the packet or the reviewer's output. Do not loop more than twice; unresolved items go to the pack as they are.
5. **Final grade, always** (stage `Final grade`). Whatever happened above, run `python src/commentary_retry.py final <client> <month> --outputs-root <RUN>/_work` on the final commentary text. It writes `<DIR>/commentary_final_grade_<month>.json` and does not count as an attempt. Every saved run must have this final grade.
6. **Build the pack** (stage `Package`; if build refuses, still run `mark ... end --status refused`). Run `python src/monthly_review.py build <client> <month> --commentary <DIR>/commentary_<month>.md --review <DIR>/review_<month>.json --outputs-root <RUN>/_work`. It writes `<DIR>/monthly_review_<month>.xlsx` and `<DIR>/owner_memo_<month>.md`. If build refuses, report the reason and still do step 7.
7. **Finish the run.** Run `python scripts/new_run.py finish <RUN>` (add `--with-regress` if the arguments had it; it takes about 9 minutes; add `--failed "<reason>"` if any step above could not be completed). It MOVES the files from `_work` into the layout (01_intake, 02_numbers, 03_commentary, 04_review, 06_pack), runs this run's evals into `05_evals` (golden evals, grader on the final commentary, flawed control, workbook hash before/after), writes `SUMMARY.md` and `run.json`, and prints the folder path and a 6-line summary.
8. **Report** the six summary lines `finish` printed, plus the pack path. Say the run is shown in the UI (`streamlit run 05_review_workspace/app/Home.py`, selector "Run N"). Do not sign off for anyone.

Rules: never run `scripts/approve.py`; the sign-off cells stay empty. The source workbook is read-only; write only under `<RUN>`; never delete `runs/` or any run folder; never open `.env`, token or credential files; do not edit `/monthly-analysis` or anything under `outputs/`.
