---
description: Demo run for a client and month. Same steps as /monthly-analysis, but every file goes into its own numbered folder demo_runs/output_NNN/ and shows as its own page in the UI
argument-hint: <client> <YYYY-MM>   (example: abc 2026-06)
allowed-tools: Bash(python scripts/new_run.py *), Bash(python src/monthly_review.py *), Bash(python src/commentary_retry.py *), Read, Write, Edit, Agent
---

Run a demo analysis for **$ARGUMENTS** (client id, then month as YYYY-MM). Work from the repo root. If either argument is missing, stop and ask.

`<RUN>` below means the folder printed in step 0, for example `demo_runs/output_003`, and `<DIR>` means `<RUN>/<client>`. Every file goes under `<RUN>` and nothing is written to `outputs/`. Pass `--outputs-root <RUN>` to every script that takes it.

0. **Create the run folder.** Run `python scripts/new_run.py <client> <month>`. It makes the next free `demo_runs/output_NNN/`, runs intake and calculate into it (writes `<DIR>/analysis.xlsx`, `<DIR>/review_packet_<month>.json`, `<DIR>/flux_<month>.json`, `<RUN>/run.json`) and prints the folder path. If it refuses (invalid client or month, unknown client) or reports a failed pipeline, stop and report; do not fall back to `outputs/`.
1. **Draft the commentary** following the `monthly-financial-analysis` skill, using only the packet's numbers. Write `<DIR>/commentary_<month>.md` in the fixed section order with a `##` heading for each: Headline · Revenue · Margins · Opex · Cash & runway · One-offs · Questions. Under the headings, one statement per line, numbered `1.`, `2.`, `3.` … continuing across sections, no other numbered lines. Include the same-month-last-year comparison (packet `yoy`) and net income excluding one-offs (packet `adjusted_net_income`). Cover revenue, gross profit, operating expenses and net income with MoM and margins; name all three `top_movements`; state TTM only if the packet has it; state the cash balance and runway if the packet has `cash`; mention each data-quality warning and any one-off in the month. Describe what changed, never why. Put no causes, forecasts or recommendations in the statements.
2. **Grade, retry once.** Run `python src/commentary_retry.py grade <client> <month> --outputs-root <RUN>`. If it passes, go on. If it fails, it prints the grader's exact mismatches: fix exactly those items, ONCE, rewrite the commentary file with Write, then run `python src/commentary_retry.py regrade <client> <month> --outputs-root <RUN>`. If the regrade still fails, do not try again: the record says `NOT APPROVED` with `needs_human`. Continue anyway and say in the report that a human must fix the commentary.
3. **Review.** Spawn the `finance-reviewer` subagent with the two file paths (packet and commentary) and no other context. It must cite a statement number for every change and return the four checklist scores (numbers, coverage, causes, tone). Save its JSON block, unchanged, as `<DIR>/review_<month>.json` AND as `<DIR>/review_<month>_first.json` (the UI compares first and final).
4. **Revise once.** If the verdict is `changes`, fix only what the changes list says, rewrite the whole commentary file with Write (keep the numbering), and run the reviewer again. Save the new review unchanged as `<DIR>/review_<month>.json` only; leave `_first.json` as it is. Never edit the packet or the reviewer's output. Do not loop more than twice; unresolved items go to the pack as they are.
5. **Final grade, always.** Whatever happened above, run `python src/commentary_retry.py final <client> <month> --outputs-root <RUN>` on the final commentary text. It writes `<DIR>/commentary_final_grade_<month>.json` and does not count as an attempt. Every saved run must have this final grade.
6. **Build the pack.** Run `python src/monthly_review.py build <client> <month> --commentary <DIR>/commentary_<month>.md --review <DIR>/review_<month>.json --outputs-root <RUN>`. It writes `<DIR>/monthly_review_<month>.xlsx` and `<DIR>/owner_memo_<month>.md`. If build refuses, report the reason and still do step 7.
7. **Record the run.** Run `python scripts/new_run.py finish <RUN>`. It fills `<RUN>/run.json` with the grade attempts, retry used, first and final reviewer verdicts, final grade, pack path and open-question count, read from the files above.
8. **Report** in six lines: run folder, commentary grade (first pass, retry used yes/no, final grade), reviewer verdicts (first, final), numbers matched, open-question count, and the pack path. Say the run is shown in the UI (`streamlit run 05_review_workspace/app/Home.py`, page "Output NNN"). Do not sign off for anyone.

Rules: never run `scripts/approve.py`; the sign-off cells stay empty. The source workbook is read-only; write only under `<RUN>`; never open `.env`, token or credential files; do not edit `/monthly-analysis` or anything under `outputs/`.
